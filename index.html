Layer Archive

2026.05 – 현재

실서비스 운영 중그림 수업 관리 시스템(LMS) 겸 게임화 커뮤니티 · 일러스트 강사 의뢰 · 개인 개발

강의 수강생이 과제를 제출하고 작품을 아카이빙하는 서비스를 직접 만들고 운영하며, 운영 환경에서 드러난 동시성·장애·성능 문제를 원인부터 해결했습니다.

  • 동시 좋아요 요청의 중복 카운트 → 멱등 API로 재설계

    동시 요청에서 발생한 StaleObjectStateException과 중복 카운트를 실제 Postgres 부하 테스트로 재현했습니다. 벌크 삭제·비관적 락을 거쳐, 토글 API를 "원하는 최종 상태를 지정하는" 멱등 API로 재설계해 재시도에도 안전한 구조로 근본 해결했습니다.

  • 배포 환경에서만 나는 500 에러 → 통합 테스트 도입

    Postgres 배포 환경에서만 갤러리·아카이브 조회 API가 실패하는 장애를 로그의 함수 오류 메시지까지 추적해 H2/Postgres 타입 추론 차이를 원인으로 특정했습니다. 같은 유형의 회귀를 막기 위해 Testcontainers 기반 Postgres 통합 테스트를 도입했습니다.

  • N+1 쿼리 → 목록 전용 DTO 분리

    게시글마다 이미지 컬렉션을 지연 로딩하던 목록 API를 경량 DTO로 분리했습니다. 두 경로를 로컬 벤치마크로 비교해 게시글 50건 기준 쿼리 53회 → 4회, 응답 55ms → 25ms를 확인했습니다.

  • 사용자 기준으로 고친 운영

    익명으로 불편 사항을 남기는 창구를 만들어 의견을 모으고, 로그인 방식 간소화와 영문 화면의 한글화처럼 실제 요청이 들어온 것부터 반영했습니다.

  • AI 에이전트와 협업하는 개발 구조

    Claude Code와 Codex 두 coding agent가 같은 규칙 원본을 공유하도록 재설계하고, 세션마다 읽던 컨텍스트를 101KB에서 3.2KB 핵심 인덱스로 줄여 실제 작업에 쓸 컨텍스트를 확보했습니다.
